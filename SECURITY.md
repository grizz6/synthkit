# Security policy

## Reporting a vulnerability

Please report security issues privately via [GitHub's private vulnerability reporting](https://github.com/grizz6/synthkit/security/advisories/new)
rather than opening a public issue. If that's not available, open an issue that describes
the impact without including exploit details, and a maintainer will follow up for specifics
privately.

## What's in scope

synthkit fits a statistical profile from real data and samples synthetic rows from it. Things
worth reporting:

- A code path where fitting a profile causes real values from the input dataframe to be
  stored verbatim in the profile (a privacy leak — the whole point of a profile is that it
  contains no real records).
- `Derived`/`ConditionalNull` constraint expressions executing unintended code beyond normal
  `pandas.eval` arithmetic (these already run through pandas' own expression evaluator, which
  has its own security surface — see [docs/LIMITATIONS.md](docs/LIMITATIONS.md) for the
  documented, expected behavior of that evaluator; a genuine sandbox escape is in scope, the
  documented eval semantics are not).
- Denial-of-service via a crafted profile.json or dataset that causes unbounded memory growth
  or a hang (as opposed to slow-but-bounded behavior on a large real dataset — see
  `docs/LIMITATIONS.md`'s performance section for what "large" already means and is expected
  to cost).

## What's out of scope

- `synthkit.check()`'s privacy guarantees are statistical, not cryptographic. A DCR ratio
  above the threshold means synthetic rows are, on average, about as far from training data
  as real holdout rows are — it is not a formal differential-privacy guarantee, and
  synthkit does not claim to be one (see `docs/LIMITATIONS.md`).
- Loading a `constraints.yaml` file or a `profile.json` from an untrusted source is not a
  supported threat model; both are meant to be authored or generated by someone with
  legitimate access to the underlying real data, the same way a `requirements.txt` or a
  `Makefile` from an untrusted source isn't safe to blindly run either.
